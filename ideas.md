# IOPAF Portal Design Direction

## Chosen Direction — Assurance Graph

**Design movement.** Technical editorial systems with an enterprise assurance-map
motif: framed nodes, causal connectors, probability bars and traceable metadata.

**Core principles.** The interface separates maturity, evidence, effectiveness and
risk; every calculation exposes its source; one assessment object remains visible
throughout the workflow; uncertainty is shown rather than hidden.

**Color philosophy.** Deep navy frames the institution. Teal signals assurance,
evidence and primary action. Red is reserved for residual risk, consequence and
exceptions. Amber is restricted to draft or provisional status.

**Typography system.** Serif display headings distinguish executive interpretation;
sans-serif body text supports reading; mono labels identify control IDs, probability
states, model versions and traceability metadata.

**Brand essence.** Evidence-based IT practice and control assurance for teams that
need defensible, component-level maturity and risk decisions. Precise, transparent,
professional.

## Style Decisions

- One primary IOPAF wordmark owns the header. ITIL, CMMI and other frameworks are
  supporting assessment references, not co-equal header brands.
- Assurance-graph primitives recur in Controls empty states, object assessment,
  Bayesian Results and model-evidence views.
- Deep navy is institutional framing, teal is assurance/action, red is risk, and
  amber is draft/provisional status. Decorative blue variation is minimized.
- Controls uses one explicit assurance path—decision target → control source →
  test evidence → failure posterior → decision/action—as the primary visual
  grammar rather than treating assessment panels as unrelated form cards.
- Control-page language uses evidence-ledger terminology: decision target,
  traceable source, test evidence, posterior and accountable action.
- Results uses the same assurance-graph grammar as Controls. Risk Register rows
  connect scenario, mapped controls, evidence, likelihood, consequence, posterior,
  appetite and status as one traceable chain rather than isolated table columns.
- The Results palette remains doctrinal: deep navy frames the model, teal owns
  active assurance and causal connectors, red is limited to posterior risk and
  appetite exceptions, and amber is reserved for provisional model status.
- Results copy prefers model-evidence terms—decision target, mapped controls,
  posterior, residual risk and accountable action—over generic dashboard labels.
- The Bayesian Network is a true modelling canvas rather than a dashboard
  pipeline. It exposes individual control parents, group posteriors, aggregate
  barriers, likelihood, consequence and residual risk as five labelled causal
  layers, with the selected path visually dominant.
- Probability nodes use named state rows and in-node bars. Supporting controls,
  exports and selectors remain visually subordinate to the assurance path.
- The Results Controls Dashboard uses a connected command path above the control
  estate: decision target → evidence-gated maturity → critical exposure →
  accountable assessment action.
- Control tiles are evidence-ledger nodes rather than catalogue cards: every tile
  carries classification, effective maturity, evidence state, evidence gate and a
  compact assurance signal.
- Risk-heavy control groups receive a restrained priority-path treatment so the
  148-control grid can be scanned by meaning without hiding any controls.
- The IOPAF wordmark uses a precise teal evidence-rule detail while framework
  references remain subordinate assessment metadata.
- The enhanced control estate reads as eight connected assurance lanes. Each
  domain explicitly links traceable source → evidence gate → assurance
  interpretation → accountable risk path before presenting its control nodes.
- Control-tile color expresses current assurance state rather than repeating
  classification texture: teal means evidenced assurance, amber means provisional
  or unevidenced, red means an assessed gap, and neutral grey means unassessed or
  not applicable. Critical/Core/Non-critical remains a textual priority attribute.
- Dashboard taxonomy summaries disclose zero-count categories, including PPE,
  rather than hiding them or assigning inapplicable labels merely to fill a chart.
